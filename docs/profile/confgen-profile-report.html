Primary finding: flush logs once per command.

The current path calls logger.Sync() after every log record. ZapDriver.Print represents 58.18% of sampled CPU and logger.Sync alone represents 50.01%. Removing per-record sync in the controlled experiment reduced normal wall time from 14.85 seconds to 6.13 seconds without materially changing allocations.

How to read sheet timing

Sheet wall time can include cold refer loads and time waiting for another goroutine. AssistSkill.xlsx spent about 2.25 seconds elapsed but almost no sampled CPU; its stack ended in waitForReferEntry.

On Windows, the thread CPU clock resolves at 15.625 ms, so most individual sheets report zero. Rank parser CPU through pprof labels and report refer load and refer wait separately.

Optimization order

Flush logs once at command shutdown

Move sync out of the per-record path and preserve explicit flushes for fatal exits.

P0

Separate parse, refer load, and refer wait

Add pprof phase labels and a block profile; avoid per-sheet OS-thread locking on Windows.

P0

Reduce Excel materialization

Plan required sheets, decode only those sheets, reduce duplicate row objects, and close workbooks early.

P1

Compile and reuse sheet parse plans

Resolve descriptors, layouts, columns, prefixes, optional fields, and refer keys once per schema.

P1

Prewarm refer dependencies

Load independent targets concurrently while keeping one parse per canonical message and column key.

P1

Collapse JSON output passes

Replace repeated encode, parse, compact, and indent passes with one semantic transform and final encoding.

P2
Validate every phase with normal and profiled runs plus byte-identical output checks. Open the detailed plan
